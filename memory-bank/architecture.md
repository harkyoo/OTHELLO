# 아키텍처 메모

## 문서 목적
- 이 문서는 현재 오델로 프로젝트의 파일 책임과 구조적 의도를 설명한다.
- 새로 합류하는 개발자가 어디에 무엇을 구현해야 하는지 빠르게 이해할 수 있도록 돕는다.

## 현재 아키텍처 상태
- 현재 구현은 구현 계획의 1단계까지만 진행된 상태다.
- 즉, 실행 가능한 React 애플리케이션 셸은 존재하지만 게임 규칙 계층은 아직 비어 있다.
- 이 시점의 목표는 이후 단계에서 규칙 로직과 UI가 자연스럽게 분리될 수 있도록 안정적인 진입 구조를 먼저 만드는 것이다.

## 상위 구조
```text
/
  index.html
  package.json
  vite.config.js
  src/
    App.jsx
    main.jsx
    components/
    game/
    hooks/
    styles/
  public/
  tests/
  memory-bank/
```

## 파일별 역할

### 루트 파일
- `package.json`
  - 프로젝트 의존성과 실행 스크립트를 관리한다.
  - 현재는 `dev`, `build`, `preview` 스크립트만 포함해 초기 개발 흐름을 단순하게 유지한다.
- `vite.config.js`
  - Vite와 React 플러그인을 연결하는 빌드 진입 설정이다.
- `index.html`
  - 브라우저 진입점이다.
  - React 앱이 마운트될 `#root` 컨테이너만 제공한다.
- `.gitignore`
  - 로컬 의존성 및 빌드 산출물을 버전 관리 대상에서 제외한다.

### `src/`
- `src/main.jsx`
  - React 애플리케이션의 실제 엔트리 포인트다.
  - 전역 CSS를 로드하고 `App`을 `#root`에 마운트한다.
- `src/App.jsx`
  - 현재 단계에서는 프로젝트 초기화 완료 메시지를 보여주는 앱 셸이다.
  - 이후 단계에서는 게임 화면의 상위 레이아웃과 주요 컴포넌트 조합 지점이 된다.

### `src/styles/`
- `reset.css`
  - 브라우저 기본 스타일 차이를 줄이기 위한 최소 리셋을 담당한다.
- `globals.css`
  - 전역 토큰, 기본 배경, 레이아웃, 타이포그래피를 담당한다.
  - 현재는 초기 앱 셸 표현에 필요한 공통 스타일만 포함한다.

### 예약된 디렉터리
- `src/components/`
  - 시각적 UI 컴포넌트를 둔다.
  - 예: `Board`, `Cell`, `ScoreBoard`, `StatusBar`, `RestartButton`
- `src/game/`
  - 오델로 규칙 엔진을 둔다.
  - 보드 생성, 유효 수 계산, 뒤집기, 패스, 종료 판정 등 순수 로직이 위치해야 한다.
- `src/hooks/`
  - React UI와 게임 로직을 연결하는 커스텀 훅을 둔다.
  - 핵심 후보는 `useOthelloGame`이다.
- `tests/game/`
  - 게임 로직 중심 테스트를 둔다.
  - UI 테스트보다 규칙 테스트를 먼저 누적하는 구조를 권장한다.
- `public/`
  - 정적 자산이 필요해질 경우 사용하는 디렉터리다.

## 설계 의도

### 1. UI와 게임 규칙의 분리
- 가장 중요한 원칙은 React 컴포넌트 안에 오델로 규칙을 흩뿌리지 않는 것이다.
- 규칙 계산은 `src/game/`에서 끝내고, UI는 그 결과를 렌더링하는 데 집중해야 한다.
- 이 경계를 지켜야 AI 모드, 수순 기록, Undo 같은 기능을 뒤에 붙이기 쉬워진다.

### 2. 단일 진실 공급원 유지
- 게임의 실제 상태는 한 흐름에서만 관리되어야 한다.
- 보드, 현재 턴, 종료 여부 같은 핵심 상태는 커스텀 훅 또는 상태 전이 함수에서 일관되게 다루고, 점수나 유효 수는 파생 계산으로 처리하는 편이 유지보수에 유리하다.

### 3. 순수 함수 우선
- `src/game/` 하위 로직은 가능한 한 순수 함수로 작성해야 한다.
- 같은 입력에 같은 출력을 반환하는 구조를 유지하면 테스트가 쉬워지고, UI 결합 없이 규칙 엔진만 검증할 수 있다.

## 다음 단계에서 추가될 책임
- `src/game/constants.js`
  - 플레이어 값, 보드 크기, 방향 벡터
- `src/game/board.js`
  - 빈 보드 생성, 초기 배치, 범위 검사
- `src/game/rules.js`
  - 유효 수 판별, 뒤집기 계산, 착수 적용, 점수 계산
- `src/game/gameState.js`
  - 턴 진행, 패스 처리, 종료 판정이 포함된 상태 전이
- `src/hooks/useOthelloGame.js`
  - UI 이벤트와 게임 상태를 연결하는 훅

## 유지보수 관점 통찰
- 지금처럼 초기에 디렉터리 경계를 먼저 고정해두면, 이후 기능 추가 시 파일 위치를 두고 흔들릴 가능성이 줄어든다.
- 보드 렌더링보다 규칙 엔진을 별도 계층으로 먼저 생각하면, 테스트와 디버깅 비용이 크게 줄어든다.
- MVP 단계에서는 파일 수가 조금 늘어나더라도 책임이 선명한 구성이 장기적으로 더 싸다.
