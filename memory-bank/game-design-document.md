# 오델로 게임 기획서 (GDD)

## 1. 게임 개요
브라우저에서 플레이할 수 있는 2인용 오델로 게임을 제작한다.  
초기 버전은 인간 대 인간(Player vs Player, PvP) 모드를 제공하며, 이후 AI 대전 모드로 확장할 수 있도록 게임 로직과 UI를 분리된 구조로 설계한다.

## 2. 목표
- 오델로의 기본 규칙을 정확하게 구현한다.
- 누구나 바로 플레이할 수 있는 직관적인 웹 UI를 제공한다.
- 추후 AI 플레이어, 난이도 선택, 기록 기능 등을 추가할 수 있도록 확장 가능한 구조를 갖춘다.

## 3. 대상 플랫폼
- 웹 브라우저
- 데스크톱 환경 우선 지원
- 모바일 환경에서도 기본적인 플레이가 가능하도록 반응형 UI를 고려한다

## 4. 핵심 게임 규칙

### 4.1 보드 구성
- 게임 보드는 8x8 격자이다.
- 각 칸은 빈 칸 또는 흑/백 돌 중 하나의 상태를 가진다.

### 4.2 초기 상태
- 게임 시작 시 중앙 4칸에 돌을 아래와 같이 배치한다.
- 백 돌: `(3,3)`, `(4,4)`
- 흑 돌: `(3,4)`, `(4,3)`
- 흑이 선공이다.

좌표 표기는 구현 시 0-index 또는 1-index 중 하나로 통일하되, 내부 로직과 UI 표기는 일관성을 유지해야 한다.

### 4.3 턴 진행
- 플레이어는 자신의 차례에 빈 칸 하나를 선택해 돌을 놓는다.
- 돌은 오직 유효한 위치에만 놓을 수 있다.
- 착수 후 상대 돌을 뒤집고 턴이 상대에게 넘어간다.

### 4.4 유효한 착수 조건
- 빈 칸에만 돌을 놓을 수 있다.
- 돌을 놓았을 때 상, 하, 좌, 우, 대각선 포함 총 8방향 중 하나 이상에서 상대 돌을 자신의 돌로 감싸야 한다.
- 즉, 새로 놓는 돌과 기존 자신의 돌 사이에 상대 돌이 연속으로 존재해야 하며, 그 방향의 끝은 반드시 자신의 돌이어야 한다.
- 어느 방향에서도 상대 돌을 감싸지 못하면 해당 위치에는 놓을 수 없다.

### 4.5 돌 뒤집기 규칙
- 돌을 놓은 뒤, 유효 조건을 만족한 모든 방향의 상대 돌을 한 번에 뒤집는다.
- 한 수에서 여러 방향의 돌이 동시에 뒤집힐 수 있다.

### 4.6 둘 수 없는 경우
- 현재 플레이어가 둘 수 있는 위치가 없으면 턴을 자동으로 상대 플레이어에게 넘긴다.
- 이를 패스(pass)로 처리한다.
- 한 플레이어가 패스하더라도 상대 플레이어가 둘 수 있으면 게임은 계속 진행된다.

### 4.7 게임 종료 조건
아래 조건 중 하나를 만족하면 게임이 종료된다.
- 보드의 모든 칸이 채워진 경우
- 흑과 백 모두 더 이상 둘 수 있는 위치가 없는 경우

### 4.8 승패 조건
- 게임 종료 시 보드 위 돌의 개수를 비교한다.
- 더 많은 돌을 가진 플레이어가 승리한다.
- 두 플레이어의 돌 개수가 같으면 무승부이다.

## 5. 기능 요구사항

### 5.1 필수 기능
- 8x8 오델로 보드 표시
- 흑/백 플레이어 턴 관리
- 유효한 착수 위치 판별
- 돌 배치 및 뒤집기 처리
- 패스 처리
- 게임 종료 판정
- 승패 또는 무승부 결과 표시
- 게임 재시작 기능

### 5.2 UI 표시 요소
- 현재 턴인 플레이어 표시
- 흑/백 돌 개수 표시
- 게임 상태 메시지 표시
  - 예: `흑 차례`, `백 차례`, `둘 수 있는 곳이 없어 턴을 넘깁니다`, `흑 승리`, `무승부`
- 재시작 버튼 제공

### 5.3 선택 기능
초기 버전에서는 제외 가능하지만 확장 요소로 고려한다.
- 유효한 착수 가능 위치 하이라이트
- 마지막 착수 위치 표시
- 착수 및 뒤집기 애니메이션
- 수순 기록
- Undo 기능
- AI 대전 모드
- 난이도 선택

## 6. UX 요구사항
- 사용자는 클릭 또는 터치로 돌을 놓을 수 있어야 한다.
- 유효하지 않은 칸을 선택했을 경우 아무 동작도 하지 않거나, 안내 메시지를 표시한다.
- 현재 게임 상태를 사용자가 쉽게 이해할 수 있어야 한다.
- 게임 종료 후 결과를 명확히 보여주고 즉시 다시 시작할 수 있어야 한다.

## 7. 비기능 요구사항
- 게임 규칙 로직은 UI와 분리해 구현한다.
- 게임 상태는 예측 가능하고 재현 가능해야 한다.
- 잘못된 착수나 잘못된 턴 진행이 발생하지 않아야 한다.
- 주요 게임 로직은 테스트 가능해야 한다.

## 8. 개발 관점의 구조 제안

### 8.1 상태 데이터 예시
- 보드 상태: 8x8 2차원 배열
- 현재 턴: `black` 또는 `white`
- 게임 종료 여부
- 승자 정보: `black`, `white`, `draw`, `null`
- 착수 가능 위치 목록
- 패스 여부 또는 최근 액션 정보

### 8.2 핵심 로직 함수 예시
- `initializeBoard()`
- `getValidMoves(board, player)`
- `isValidMove(board, player, position)`
- `getFlippableDiscs(board, player, position)`
- `applyMove(board, player, position)`
- `getNextPlayer(board, currentPlayer)`
- `isGameOver(board)`
- `getScore(board)`

함수명은 예시이며, 사용하는 기술 스택에 맞게 조정할 수 있다.

## 9. 확장 고려사항
- AI 플레이어 추가를 위해 게임 엔진은 입력으로 현재 보드 상태와 플레이어 정보를 받아 다음 수를 계산할 수 있는 구조가 바람직하다.
- 온라인 대전이나 저장 기능을 고려한다면 상태 직렬화가 가능하도록 설계한다.
- 애니메이션이나 사운드는 핵심 규칙 구현 이후 추가한다.

## 10. 출시 범위 정의

### 10.1 MVP 범위
- 로컬 2인 플레이
- 규칙에 맞는 착수/뒤집기
- 턴 표시
- 점수 표시
- 종료 판정
- 재시작

### 10.2 추후 확장 범위
- AI 대전
- 애니메이션
- 효과음
- 모바일 UX 개선
- 기록 저장
- 온라인 대전

## 11. 완료 기준
아래 항목을 만족하면 MVP 완료로 본다.
- 사용자가 브라우저에서 2인 오델로 게임을 처음부터 끝까지 정상적으로 플레이할 수 있다.
- 모든 착수는 오델로 규칙에 맞게 검증된다.
- 돌 뒤집기, 패스, 종료, 승패 판정이 정확히 동작한다.
- 게임 종료 후 재시작이 가능하다.
