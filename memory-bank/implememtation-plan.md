# 오델로 게임 구현 계획서

## 1. 문서 목적
- 이 문서는 `memory-bank/game-design-document.md`를 기반으로 오델로 게임 MVP를 실제로 구현하기 위한 구체적인 작업 계획을 정의한다.
- 목표는 React 기반 웹 애플리케이션으로 오델로 게임을 구현하되, 규칙 정확성, 유지보수성, 확장성을 모두 확보하는 것이다.

## 2. 구현 목표
- 브라우저에서 2인이 번갈아 플레이할 수 있는 오델로 게임을 완성한다.
- 오델로 핵심 규칙인 착수 검증, 돌 뒤집기, 패스, 종료 판정, 승패 계산을 정확히 구현한다.
- React 컴포넌트와 순수 게임 로직을 분리해 이후 AI 모드나 기록 기능을 추가하기 쉬운 구조를 만든다.

## 3. MVP 범위
- 8x8 보드 렌더링
- 흑/백 턴 진행
- 유효한 착수 위치 판별
- 착수 후 뒤집기 처리
- 패스 처리
- 게임 종료 판정
- 점수 표시
- 승패 또는 무승부 표시
- 게임 재시작

## 4. 비범위 항목
- AI 대전
- 수순 기록
- Undo 기능
- 사운드
- 온라인 대전
- 저장 기능
- 고급 애니메이션

## 5. 기술 방향
- 프레임워크: `React`
- 언어: `JavaScript (ES6+)`
- 마크업 및 스타일링: `HTML5`, `CSS3`
- 개발 환경: `Vite`
- 패키지 매니저: `npm`
- 테스트: `Vitest` 기반 단위 테스트 우선

## 6. 아키텍처 원칙
- 게임 규칙 로직은 UI와 분리한다.
- UI는 상태를 표시하고 사용자 입력을 전달하는 역할에 집중한다.
- 보드 상태와 턴 상태는 예측 가능한 단일 상태로 관리한다.
- 규칙 계산 함수는 가능한 한 순수 함수로 작성한다.
- 계산 가능한 값은 저장하지 않고 파생 값으로 처리한다.

## 8. 상태 설계

### 8.1 핵심 상태
- `board`: 8x8 2차원 배열
- `currentPlayer`: `black` 또는 `white`
- `gameOver`: 게임 종료 여부
- `winner`: `black`, `white`, `draw`, `null`
- `message`: 현재 상태 메시지
- `lastMove`: 마지막 착수 위치 또는 `null`

### 8.2 파생 값
- `validMoves`
- `score`
- `canCurrentPlayerMove`
- `canOpponentMove`

### 8.3 상태 관리 원칙
- `validMoves`, `score`, `winner`는 가능하면 계산 함수에서 도출한다.
- React 컴포넌트는 직접 규칙을 계산하지 않고 훅 또는 게임 로직 모듈에서 계산된 값을 사용한다.

## 9. 데이터 표현 규칙
- 좌표 체계는 내부적으로 `0-index`를 사용한다.
- 보드 셀 값은 아래 셋 중 하나로 통일한다.
  - `null`
  - `black`
  - `white`
- 방향 탐색은 8개 방향 벡터 배열로 관리한다.
- 플레이어 전환은 문자열 분기 대신 헬퍼 함수로 처리한다.

## 10. 핵심 모듈 설계

### 10.1 `constants.js`
- 보드 크기
- 플레이어 상수
- 방향 벡터
- 기본 메시지 상수

### 10.2 `board.js`
- 초기 보드 생성
- 보드 복사 유틸리티
- 좌표 범위 검사
- 특정 칸 읽기/쓰기 보조 함수

예상 함수:
- `createEmptyBoard()`
- `createInitialBoard()`
- `isInBounds(row, col)`
- `cloneBoard(board)`

### 10.3 `rules.js`
- 유효한 착수 판별
- 뒤집을 돌 계산
- 전체 유효 수 계산
- 착수 적용
- 점수 계산
- 게임 종료 판정

예상 함수:
- `getOpponent(player)`
- `getFlippableDiscs(board, player, position)`
- `isValidMove(board, player, position)`
- `getValidMoves(board, player)`
- `applyMove(board, player, position)`
- `getScore(board)`
- `hasAnyValidMove(board, player)`
- `isGameOver(board)`
- `getWinner(board)`

### 10.4 `gameState.js`
- 한 턴 진행 흐름 제어
- 패스 처리
- 상태 메시지 생성
- 재시작 상태 생성

예상 함수:
- `createInitialGameState()`
- `playTurn(state, position)`
- `getNextTurnState(state)`
- `restartGame()`

### 10.5 `selectors.js`
- UI에서 자주 필요한 파생 데이터 제공
- 점수, 현재 플레이어 표시 문구, 종료 메시지 등 계산

## 11. React 컴포넌트 설계

### 11.1 `App.jsx`
- 게임 전체 레이아웃 구성
- `useOthelloGame` 훅 연결
- 보드, 점수판, 상태 메시지, 재시작 버튼 조합

### 11.2 `Board.jsx`
- 8x8 보드를 화면에 렌더링
- 각 셀에 현재 값, 착수 가능 여부, 클릭 핸들러 전달

### 11.3 `Cell.jsx`
- 개별 칸 UI 표시
- 돌 유무 렌더링
- 클릭 또는 터치 입력 처리
- 필요 시 유효한 착수 위치 하이라이트 표시

### 11.4 `ScoreBoard.jsx`
- 흑/백 점수 표시
- 현재 턴 강조

### 11.5 `StatusBar.jsx`
- 현재 턴 메시지
- 패스 메시지
- 승패 메시지

### 11.6 `RestartButton.jsx`
- 게임 초기화 액션 실행

## 12. 커스텀 훅 설계

### 12.1 `useOthelloGame.js`
- 게임 상태 보관
- 플레이어 입력 처리
- 유효 수 계산 결과 제공
- 재시작 함수 제공

반환 예시:
- `board`
- `currentPlayer`
- `validMoves`
- `score`
- `message`
- `gameOver`
- `winner`
- `lastMove`
- `handleCellClick(position)`
- `restartGame()`

산출물:

- 테스트 가능한 보드 유틸 함수

## 14. 테스트 계획

### 14.1 단위 테스트 대상
- 초기 보드 생성
- 특정 위치의 유효 수 판별
- 한 방향 뒤집기
- 다중 방향 뒤집기
- 점수 계산
- 패스 처리
- 종료 판정
- 승자 계산

### 14.2 수동 테스트 시나리오
- 게임 시작 직후 흑이 정상적으로 선공하는지
- 유효하지 않은 칸 클릭 시 상태가 변하지 않는지
- 여러 방향으로 돌이 뒤집히는 착수가 정상 동작하는지
- 둘 수 없는 턴에서 자동 패스되는지
- 양측 모두 둘 수 없을 때 종료되는지
- 종료 후 재시작 버튼으로 초기화되는지

## 15. UI/UX 계획
- 보드는 시각적으로 8x8 격자가 분명해야 한다.
- 흑/백 돌은 색상과 대비가 명확해야 한다.
- 현재 턴, 점수, 게임 상태는 보드 외부에서 항상 보이게 한다.
- 클릭 가능 영역은 모바일에서도 충분한 크기로 유지한다.
- 잘못된 입력은 무시하거나 간단한 안내 메시지로 처리한다.

## 16. 리스크와 대응
- 규칙 로직이 UI에 섞이면 유지보수가 어려워진다.
  - 대응: 규칙 계산은 반드시 `game/` 모듈에서 처리한다.
- 패스와 종료 조건이 누락되기 쉽다.
  - 대응: 상태 전이 함수와 테스트에서 별도 검증한다.
- 컴포넌트가 비대해질 수 있다.
  - 대응: 책임 단위로 컴포넌트를 일찍 분리한다.

## 17. 확장 준비 사항
- AI 추가를 위해 현재 상태를 입력받아 다음 수를 계산할 수 있는 인터페이스를 유지한다.
- 상태 직렬화가 가능하도록 보드와 턴 상태 구조를 단순하게 유지한다.
- 수순 기록 기능을 위해 `lastMove` 및 향후 히스토리 배열 추가가 가능한 형태를 고려한다.

## 18. 완료 판정
- 로컬 2인용 오델로 게임이 브라우저에서 정상 동작한다.
- 모든 착수가 규칙에 맞게 검증된다.
- 돌 뒤집기, 패스, 종료, 승패 판정이 정확하다.
- 현재 턴, 점수, 상태 메시지, 재시작 기능이 제공된다.
- 게임 로직과 React UI가 분리된 구조로 유지된다.
